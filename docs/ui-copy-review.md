# UI 文案交接

`node scripts/ui-copy-catalog.mjs` 只扫描工具箱的 renderer、main、shared 源码，不读取账号数据、令牌文件或运行日志

提取结果位于忽略目录 `out/ui-copy-catalog/catalog.json`，包含稳定文案 ID、原文、动态参数、精确源码位置和文件 SHA-256。表格构建器将其输出为单个双语 XLSX

## 修改规则

- 只修改“中文修改”和“英文修改”两列，其他列保留
- 修改列预填原文；空白视为不修改，需删除时使用 `[[DELETE]]` 并在交接时说明
- 保留 `{p1}`、`{p2}` 等动态参数，可调整顺序，不增删或重命名
- 不填写密码、令牌、Cookie、验证码、急救码或个人留言
- 动态昵称、Steam 服务端返回内容、外部 Steam.Design 网页及游戏自身的模板不属于本工具箱静态文案

## 应用返回表格

先校验 catalogId、文案 ID、原文和动态参数，再核对源码哈希及当前内容。只应用明确修改的条目，不根据行号或纯文本全局替换

“联动复核”包括错误匹配键、正则翻译、原生确认以及安全说明；品牌名称还可能参与数据兼容和更新校验。此类修改必须复核关联逻辑，不直接替换协议、校验规则或安全分支

表格中的位置列可按文件合并展示 line:column；完整位置保留在 manifest 中，不将位置展示列作为唯一映射键

## 标题栏

主窗口使用无边框窗口与工具箱自己的标题栏，复用现有 Logo 和明暗配色。所有窗口操作只走校验发送者的 windowUi IPC；关闭仍进入原有事务保护、首次选择和系统托盘流程，不直接销毁窗口

业务导入、安装期间仍允许窗口控制 IPC，但实际关闭由原有 Main close 事件检查。渲染应用的加载页和错误页也包在标题栏之下；若 preload 本身失败，桥接操作不可用，可使用错误页重新载入或系统 Alt+F4

没有为标题栏增加持续轮询、动画、透明模糊或独立网络请求
