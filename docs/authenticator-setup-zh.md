# 本地手机令牌完整流程

## 已有令牌

在“本地手机令牌 → 验证码”选择原始 `.maFile`。确认后，工具箱将文件中可用的验证码密钥、确认密钥、设备和急救资料重新加密保存在本机，不保存导入文件里的登录会话令牌或 Cookie，也不修改原文件

v0.17 的旧记录仅保存了验证码密钥，不能据此补造急救码或交易确认密钥。请重新导入原文件补齐资料。每条记录会分别标注已有能力；单独导出一个缺字段的旧记录，不会神奇地变成完整 SDA 备份

急救码在本机独立加密保存，通过原生窗口显式查看或复制，不进入网页界面、普通数据库导出或排查日志。这里的急救码是验证器恢复/撤销码，不是自动生成一组一次性备用登录码

## 首次新绑定

1. 打开“新建手机令牌”，输入目标 Steam 登录名、密码，可填写 SteamID64 校验。工具箱建立独立的 MobileApp 身份认证会话，不把已有网页登录令牌伪装成手机会话，也不建立第二个同号游戏 CM 连接。密码和输入的验证码不会持久保存
2. 按 Steam 返回的身份验证方式提交邮箱码、已有验证器码或完成手机确认，再显式检查登录结果。核对实际登录的 SteamID64；恢复旧任务时不能改成另一账号
3. 预检已有验证器和账号状态。已有验证器应选择导入或官方迁移，不会自动先移除再绑定。手机号并非一律强制：可显式尝试 Steam 允许的邮件/短信方式；若 Steam 明确要求手机号，再输入完整国际号码及拨号区号，点击确认邮件链接、检查邮件状态、显式发送短信、提交短信码，并重新查询手机号是否验证成功
4. 点击新建请求，并在原生窗口核对目标账号。每次只发送一项 Add 请求。收到候选秘密后，工具箱先加密写入待完成文件、同步磁盘并重新读取验证；此时还不能当作绑定已经完成
5. 私密查看并单独保存急救码，导出待激活 `.maFile` 备份。备份含明文密钥，应放在可信私密位置。工具箱会重新读取文件核对，并再要求你在原生窗口确认已保存急救码与备份。仅勾选网页复选框不能绕过这个门槛
6. 按 Steam 指定的邮件或短信方式输入激活码，确认后提交一次 Finalize。用于生成验证器码的 Steam 时间与请求中的时间保持一致。Steam 要求更多时窗时显示等待，不会快速循环提交，更不会重新 Add。明确的验证码错误可以修正；未知结果先查询状态，不盲目重复激活
7. 服务端状态已启用且令牌标识与本候选匹配后，才将条目标记为已完成并保存到主令牌库。若本地已有不同旧记录，会再要求确认替换。随后可返回“验证码”使用，并导出已激活资料备份

未知确认类型、身份不符或部分秘密格式异常时，工具箱隔离加密保留可用资料，而不是假称绑定成功。隔离救援文件是 JSON，不是有效验证器，不允许拿它直接激活或自动重新绑定

## 退出与恢复

- 托盘驻留只隐藏 GUI，不停止已有任务，也不代替磁盘备份
- 真正退出会停止后续步骤；已经提交的 Add/Finalize 会先等待有界响应与关键资料落盘，再退出
- 重启后恢复同一任务、同一设备标识，先检查待完成状态，不自动重新 Add，也不自动 Remove
- 已提交但结果不明时保留记录，需要重新登录或只读核对；不能因会话过期就丢掉候选秘密
- 收到密钥但无法安全写盘时，普通退出会被拦截，需先救援保存，或再次明确承认风险后退出
- 丢响应可能意味着服务端结果无法确认，这不是本地软件能凭空重建秘密的情况。请保留已有文件并在 Steam 核对，不要反复新建

## 交易与市场确认

选择同一令牌，并在左侧工具箱账号中选中、登录同一个 SteamID64，再手动读取确认列表。这里使用同账号 Community 会话及确认密钥，不宣称已有 MobileApp 会话，也不改动 Steam 客户端当前账号

仅交易和市场上架类型可操作；账号恢复、手机号变更等其它安全类型不混入允许列表。每项单独查看 Steam 摘要，并先到 Steam 完整页面核对物品与对象，再在原生窗口允许或拒绝。没有默认全选、自动确认或无人值守接受

提交前会再次读取核对原项目，并先持久保存防重复标记。响应不明时不会自动重发，重启或重新导入同一令牌也不等于可以重试。Steam 接受某项确认，不代表交易已经成交

## 保存和迁移

工具箱数据目录下分别保存加密令牌库、加密待绑定记录和加密确认安全记录。普通 SQLite 数据备份不包含这些秘密。Windows DPAPI 密文不保证可直接换电脑或 Windows 用户使用；跨机器请通过私密导出文件重新导入，不要把密钥文件作为排查日志发送
